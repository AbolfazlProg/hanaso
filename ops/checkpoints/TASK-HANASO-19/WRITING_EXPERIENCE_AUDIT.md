# TASK-HANASO-19 — WRITING EXPERIENCE AUDIT (ممیزی تجربهٔ نوشتن)

> روش: عبور واقعی از کل چرخهٔ نوشتن در مرورگر زنده (تدریس → آماده‌ای → تمرین هدایت‌شده → حافظه → کاراکتر بعدی) با رسم واقعی موس برای か (۳ ضربه) و き/く؛ بررسی DOM برای Free Recall؛ کد موتور + دادهٔ KanjiVG؛ مقایسه با ۱۱ پرسش مأموریت.

## ۱) پاسخ به پرسش‌های مأموریت

| پرسش | واقعیت ممیزی‌شده | وضعیت |
| --- | --- | --- |
| کل تجربه در یک محیط یکپارچه و ثابت؟ | بله — یک region واحد («کا — …») که فقط زیرعنوانش عوض می‌شود؛ هیچ jump صفحه‌ای نیست. زنده: か کامل + ورود به き. | 🟢 |
| کاربر مجبور به عبور از صفحه‌های متعدد و Nextهای غیرضروری؟ | خیر — گذارها خودکار (تدریس→آماده‌ای خودش می‌آید؛ هدایت‌شده→حافظه خودکار بعد از ضربهٔ آخر). تنها کلیک: «شروع تمرین نوشتن». | 🟢 |
| باکس Stroke اندازه و موقعیت مناسب؟ | دسکتاپ 416×416 در ستون اصلی؛ موبایل 360px: 294×294 داخل قاب. | 🟢 |
| دستورالعمل‌ها و Progress حفظ می‌شوند؟ | بله — «ضربهٔ n از N» + «از بالا شروع کن/به سمت …» + progress «۲/۳ ضربه» همیشه دیده می‌شوند. | 🟢 |
| انیمیشن Stroke Order درست؟ | بله — پخش ضربه‌به‌ضربه با شماره؛ فونت داده = KanjiVG (صحت ترتیب か با ۵ منبع بیرونی + Shogakukan تأیید شد — سند ممیزی پیش‌نیاز §۲). | 🟢 |
| Repeat فقط انیمیشن را تکرار می‌کند؟ | بله — «تکرار آموزش» دکمهٔ مستقل؛ Progress دانشجو reset نمی‌شود. | 🟢 |
| Canvas بی‌دلیل Scroll می‌کند؟ | نه — هیچ اسکرول داخلی/افقی در ۸ viewport. | 🟢 |
| پس از Stroke صحیح، نمایش استاندارد نرم و طبیعی؟ | بله — «بعد از هر ضربهٔ درست، همان ضربه با شکل استانداردش جوهری می‌شود» (dash-offset انیمیشن جوهر) — زنده دیدیم که ضربهٔ رسم‌شده با مسیر استاندارد جایگزین می‌شود. | 🟢 |
| Free Recall نقطه و جهت شروع را مخفی نگه می‌دارد؟ | **بله — به‌طور کامل.** بازرسی DOM در حالت حافظه: فقط ۲ `<line>` (خطوط راهنمای شبکه)؛ صفر circle/شماره/path پیش‌نمایش/dasharray. | 🟢 |
| پذیرش رسم واقعی؟ | بله — رسم موسِ پیرو median پذیرفته شد (か/き/ک)؛ موتور سمت کلاینت با tolerance هندسی. | 🟢 |

## ۲) جریان واقعی طی‌شده (گام‌به‌گام)

1. «آموزش نوشتن این نویسه» — انیمیشن خودکار + شمارهٔ ضربه + «شماره، نقطهٔ شروع و جهت هر ضربه را همانجا در دفتر می‌بینی» + کنترل سرعت («عادی»).
2. «آماده‌ای؟» — دکمه‌های پخش صدای کانا + ۳ مثال واژه (～かい/かう/かく) + «شروع تمرین نوشتن» + «تکرار آموزش».
3. «تمرین با راهنما» — مسیر نقطه‌چین؛ بعد از هر ضربهٔ درست → جوهرشدن استاندارد؛ «راهنما» برای کمک لحظه‌ای؛ پنل‌های بازشو: «اطلاعات معرفی (تلفظ، یادسپار، جفت مشابه)» + «نمونه‌های قابل‌خواندن» + «منابع».
4. «نوشتن از حافظه» — «اگر جایی گیر کردی، دکمهٔ راهنما همین‌جا بالای صفحه است» + گزینهٔ صادق «با راهنما تمرین می‌کنم» (خروج نرم بدون دروغ).
5. کاراکتر بعدی خودکار (か→き→く→…).

## ۳) داده و موتور

- `writing/engine.ts` + `analysis.ts`: ارزیابی هندسی با medianهای arc-length-نمونه‌گیری‌شده؛ فایل per-glyph در `public/writing-data/` (۹۲ فایل) با پرووننس KanjiVG + لایسنس CC BY-SA commit شده.
- تاریخچهٔ کیفیت: اسکریپت build می‌گوید دادهٔ قبلی AnimCJK «۱۶/۹۲ گلیف با تعداد ضربهٔ غیراستاندارد» داشت و جایگزین شد — ریشهٔ درست‌کاری فعلی.
- **نکتهٔ ممیزی:** ممیزی مستقل ترتیب ضربه‌ها را روی あ/い/き/か راستی‌آزمایی کرد: همگی با KanjiVG و استاندارد ژاپنی منطبق‌اند؛ نمونهٔ か حتی دقیقاً همان جایی است که منابع آموزشی ژاپنی هشدار « بزرگسالان اشتباه می‌کنند» می‌دهند (swoosh اول، قطع‌کننده دوم).

## ۴) یافته‌های منفی/ریسک

1. **دقت پذیرش نامعلوم برای دست واقعی:** ممیزی با موسِ دقیقِ median-محور انجام شد (تقریباً «کپی perfect»). برای دست انسانی sloppy، آستانهٔ tolerance در دستگاه لمسی باید با تست کاربر واقعی کالیبره شود — در این ممیزی قابل سنجش نبود (Not Verified).
2. **پنل «منابع»**: در دسترس است ولی محتوایش (attribution KanjiVG?) در این گذر باز نشد — بررسی نشده.
3. **هیچ راه پرش/معافیت وجود ندارد** — نوشتن برای همهٔ ۹۲ گلیف الزامی است (حتی کاربری که قبلاً کانا بلد است). Test-Out گیت تسلط این را جبران می‌کند ولی مسیر اصلی سنگین است — تصمیم مالک (DD-097/105) و مستند، ولی برای «بازگشت‌کننده‌ها» اصطکاک واقعی است.
4. ورودی نام در k13 («نامِ خودت») — با کیبورد موبایل تست نشد (Not Verified).

## ۵) جمع‌بندی
