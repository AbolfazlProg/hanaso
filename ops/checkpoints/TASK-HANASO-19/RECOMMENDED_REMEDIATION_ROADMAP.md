## P0 — موانع بحرانی یادگیری (قبل از هر کاربر جدیدی)

### P0-1 🐛 رفع باگ بازدید اول (BUG-001 + BUG-002)

- **Problem:** SSR بدون کوکی، پیشرفت کاربر مشترک `poc-user` را رندر می‌کند و CTA کاربر جدید را به درس قفل‌شدهٔ h2 می‌برد؛ تکمیلش هم 409 می‌شود.
- **Evidence:** دو بازتولید زنده با state پاک (LIVE_WEBSITE_AUDIT §۳) + کد `lib/learner/identity.ts` / `home/server.ts`.
- **Root Cause:** fallback سرور به POC_DEFAULT_USER_ID در RSC بدون کوکی + نبود refresh پس از ساخت شناسهٔ کلاینت.
- **Research Ref:** — (امنیت داده/صحت شروع؛ اصل مالک «هیچ عدد ساختگی»).
- **Affected:** `app/page.tsx`، `lib/learner/*`، همهٔ صفحات progress-محور.
- **Dependencies:** —
- **Acceptance:** (۱) بازدید اول با state پاک = حالت «شروع یادگیری» با صفر ایستگاه؛ (۲) هیچ CTA به ایستگاه بدون پیش‌نیاز نمی‌رود؛ (۳) تست E2E: کل مسیر اولین‌بازدید → h0 → تکمیل موفق.
- **Suggested Tests:** E2E Playwright با context جدید (شامل assertions روی SSR HTML اولیه)؛ unit برای resolveLearnerId بدون کوکی (باید حالت guest-خنثی بدهد نه poc-user).
- **گزینهٔ طراحی برای مالک:** به‌جای fallback به poc-user، صفحهٔ خوش‌آمد «ناشناس» (بدون عدد پیشرفت) رندر شود؛ شناسه را میدل‌ور سرور بسازد (Set-Cookie در همان پاسخ اول) تا SSR و کلاینت هم‌شناسه شوند.

### P0-2 🐛 توضیح‌دار کردن شکست ثبت (BUG-004) + هم‌ترازی لایهٔ دسترسی

- **Problem:** ورود آزاد URL به ایستگاه + ثبت مشروط → ۴۰۹ بی‌توضیح «تلاش دوباره برای ثبت».
- **Evidence:** زنده + curl (`prerequisites_not_met`).
- **Root Cause:** سه لایهٔ ناهمگون: نقشه=قفل، ورود=آزاد، ثبت=قفل.
- **Research Ref:** — (UX خطا؛ honest-principle پروژه).
- **Affected:** `station-runner.tsx` (error state)، `app/api/curriculum/station/route.ts` (پیام فارسی code→message)، `learn/[chapter]/journey/[station]/page.tsx`.
- **Acceptance:** (۱) پیام ۴۰۹ = «برای این درس اول درسِ X را تمام کن» + لینک؛ (۲) یا redirect در ورود با همان پیام؛ (۳) هیچ دکمهٔ retry بی‌هدف.
- **Suggested Tests:** unit برای نگاشت error-code→پیام فارسی؛ E2E پرش مستقیم به h6 → پیام درست.

### P0-3 📚🐛 رفع تناقض きょう + بستن گیت TRANSCRIPT (BUG-003)

- **Problem:** تدریس/کارت مرجع/promptJaReading می‌گویند «کیو»، تنها گزینهٔ درست «کیوو» — پاسخِ مطابقِ درس غلط است.
- **Evidence:** بازتولید زنده + داده (۳ بلوک + exercise) + کد گیت (`validation.ts:586` — برچسب گزینه‌ها را نمی‌بیند).
- **Root Cause:** ناهم‌راستایی آوانگاسی بلوک‌های TL-14 با قرارداد R1-03؛ کورِ گیت.
- **Research Ref:** KB13-02 آوانگاسی یکتا؛ TL-14 تصمیم ۳ (قرارداد کووکوو/سِنسِی).
- **Affected:** `chapter-kana01.stations.ts` (h6: سه readingFa + structureTable)، `chapter-kana01.exercises.ts` (ex-dec-3 promptJaReading)، `validation.ts` (گیت).
- **Acceptance:** (۱) در کل فصل فقط یک reading برای きょう (تصمیم مالک: کیوو طبق قرارداد — یا کیو + اصلاح گزینه؛ یکسان)؛ (۲) گیت گزینه‌ها را هم مقایسه کند (برچسب گزینهٔ درست باید ⊇ reading باشد یا برعکس)؛ (۳) اسکن سراسری واژه‌های یُوئون‌دار دیگر (じゅう/きゅう/ちゃ…) برای همین الگو.
- **Suggested Tests:** تست mutation جدید در `tl14-rule-teaching.test.ts`: تغییر correctOption به reading متفاوت → باید رد شود.
