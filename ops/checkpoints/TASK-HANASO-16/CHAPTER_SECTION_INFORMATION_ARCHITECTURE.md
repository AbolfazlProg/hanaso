## ۱) انتخاب مدل نمایش (§۳.۱ مأموریت — مقایسهٔ واقعی)

| معیار | مدل A (فعال+گذرانده) | مدل B (فعال + Teaser تدریجی) | نتیجه |
| --- | --- | --- | --- |
| وضوح مسیر | ✓ | ✓ | برابر |
| ایجاد کنجکاوی | خنثی — پایان فصل «دیوار» است | ✓ پیش‌نمایش محدود نزدیک پایان، انگیزهٔ ادامه | **B** |
| پنهان‌ماندن تعداد کل | ✓ | ✓ (Teaser فقط فصل بلافاصله بعدی، بدون شمارش) | برابر |
| حس پیشرفت | ✓ | ✓✓ (هدف بعدی مرئی می‌شود) | **B** |
| پیچیدگی Navigation | کم | کم (همان دو دکمه) | برابر |
| سردرگمی مبتدی | کم | کم (Teaser فقط پس از ۷۵٪ پیشرفت ظاهر می‌شود) | برابر |
| سازگاری با معماری | ✓ | ✓ (فقط Resolver خالص جدید) | برابر |

**انتخاب: مدل B اصلاح‌شده** — فصل فعال + آرشیو فصل‌های گذرانده + یک کارت Teaser از فصل بعدی که فقط وقتی پیشرفت core فصل فعال ≥ ۰٫۷۵ شود (یا همهٔ ایستگاه‌های core کامل و گیت باز باشد) آشکار می‌شود. هیچ‌جا از تعداد کل فصل‌ها/بخش‌ها/ایستگاه‌های آینده عدد نمایش داده نمی‌شود («درس ۳ از ۲۵» و امثال آن ممنوع). فصل‌های دورتر از فصل بعدی، هرگز فهرست یا پیش‌نمایش نمی‌شوند.

## ۲) ساختار سلسله‌مراتبی نهایی (Mapping روی Entityهای موجود)

```
Learning Journey (/learn)
├── فصل فعال (از Progress استخراج می‌شود — resolveRevealPlan)
│   ├── هدر: عنوان + هدف کوتاه (canDoFa) + پیشرفت core (بدون مخرج گمراه‌کننده) + پیوند «معرفی فصل»
│   ├── پنل Section فعال (در هر لحظه فقط همین یک بخش)
│   │   ├── سرصفحهٔ پنل: «بخش …» + عنوان بخش + هدف بخش (summaryFa) + وضعیت بخش
│   │   ├── Rows: ایستگاه‌های همان بخش به ترتیب walk — هر ردیف: عنوان، هدف یک‌خطی،
│   │   │        نشانگر وضعیت (انجام‌شده/فعلی/آماده/قفل/اختیاری)، دکمهٔ ورود/ادامه/مرور
│   │   │        (~دقیقه — فقط دادهٔ واقعی همان ایستگاه)
│   │   └── پانوشت پنل: [بخش قبلی ← عنوان] · [بخش بعدی ← عنوان] (مقصد مشخص؛
│   │            بخش بعدیِ قفل: دکمه فعال اما با برچسب صادقانهٔ وضعیت — نمای هر بخش مجاز،
│   │            ورود به ردیف‌های قفل طبیعتاً از طریق prereqs مسدود/بی‌اثر است)
│   └── CTA اصلی: «شروع یادگیری» / «ادامهٔ یادگیری ←» → دیپ‌لینک مستقیم nextStation
├── کارت Teaser (فقط در صورت احراز آستانه): «بعد از این فصل…» + عنوان فصل بعدی + یک خط موضوع — بدون شمارش
└── آرشیو فصل‌های گذرانده (بازشو، کم‌حجم): عنوان + وضعیت «فهمیده‌شده» + ورود برای مرور
```

- **Section = `ChapterUnit` موجود** (بدون تغییر شکل داده؛ grouping صرف مثل امروز). فصل بدون units → یک بخش ضمنی واحد.
- **Row = Station**. **Lesson = محتوای Station (blocks)**. هیچ سطح جدید Data Model ساخته نمی‌شود.
- ترتیب بخش‌ها/ردیف‌ها فقط از data (order + stationSlugs) — بدون Hardcode در Frontend.

## ۳) وضعیت‌های Section (Derived — هرگز Stored)

| وضعیت | قاعدهٔ استخراج از availability ردیف‌ها |
| --- | --- |
| `completed` | همهٔ ایستگاه‌های core بخش در {completed, skipped, needs_retry} |
| `in_progress` | بخش شامل nextStation فعلی یا ردیفِ in_progress/needs_retry، یا برخی (نه همه) coreها انجام‌شده |
| `upcoming` | بخش بعد از بخشِ فعلیِ کاربر؛ ردیف‌هایش همگی locked (نمای صادقانه، بدون ورود مؤثر) |
| `locked` | همهٔ ردیف‌ها locked (معمولاً = upcoming) |

Section فعال پیش‌فرض = اولین بخشِ غیر-completed به ترتیب data (شامل nextStation)؛ اگر همهٔ بخش‌ها completed → آخرین بخش (نمای مرور). دیپ‌لینک `?s=<slug>` هر بخشی را باز می‌کند (در فصل بازشده).

## ۴) قواعد Reveal و دسترسی

1. فصل فعال: اولین فصلِ دوره (ترتیب level.orderInCourse سپس orderInLevel) که `ChapterState.status !== 'understood'` دارد. تازه‌وارد → فصل اول. اگر همهٔ فصل‌ها understood → آخرین فصل (حالت «مسیر فعلی کامل» + آرشیو).
2. آرشیو: فصل‌های understood — لینک مرور به همان پنل بخش. مرور = ورود مجدد به ایستگاه‌ها؛ walk-persistence از قبل idempotent است (Review دوباره ثبت نمی‌کند — تست می‌شود).
3. Teaser: فصلِ بلافاصله بعد از فصل فعال، فقط وقتی `coreCompleted/coreTotal ≥ 0.75` فصل فعال. محتوا: عنوان + canDoFa کوتاه. بدون دکمهٔ ورود (فصل هنوز قفل است — DD-114: هدف مرئی، ورود نه).
4. قفل URL (Backend): مکانیزم موجود chapterAccessStatus (prerequisiteChapterSlug) در همهٔ مسیرهای فصل اعمال می‌شود — تست رگرسیون. **گیت اعتبارسنجی جدید**: هر فصل به‌جز اول باید prerequisiteChapterSlug تعریف کند (وگرنه validateChapter خطا می‌دهد) → صدقیت Reveal برای فصل‌های آینده مکانیکی تضمین می‌شود.
5. شمارنده‌های ممنوع: تعداد کل فصل‌ها، «بخش n از m»، «درس n از m». پیشرفت بخش/فصل به‌صورت نسبی بدون مخرج کل آینده (مثلاً «۳ ایستگاه این بخش انجام شد») یا نوار سهمی بدون عدد کل.

## ۵) تفکیک اسکرول و Navigation (§۲.۲)

- محتوای پنل بخش با **اسکرول عمودی طبیعی صفحه** تا انتهای همان بخش دیده می‌شود (بخش‌ها ≤ ۱۲ ردیف — بدون اسکرول‌باکس داخلیِ کوچک).
- تغییر بخش فقط با دکمهٔ «بخش بعدی/قبلی» — پس از تغییر، اسکرول به ابتدای پنل برمی‌گردد. هیچ بخش دیگری هم‌زمان رندر نمی‌شود.
- عملاً: یک بخش = یک صفحه. مقصد هر دکمه با عنوان بخشِ مقصد مشخص است؛ در دسکتاپ و موبایل در همان جای ثابت پایین پنل.

## ۶) CTA و کاهش کلیک (§۴)

| شخصا | مسیر جدید | کلیک تا محتوای درس |
| --- | --- | --- |
| کاربر جدید | `/learn` → CTA «شروع یادگیری» → StationRunner | **۱ کلیک** (قبلاً: فهرست → معرفی فصل → مکالمه → …) |
| کاربر بازگشتی | `/learn` (فصل/بخش فعال خودکار) → CTA «ادامهٔ یادگیری ←» → ردیف نیمه‌تمام | **۱ کلیک** |
| مرور فصل گذرانده | آرشیو → پنل بخش فصل → ردیف موردنظر | ۲ کلیک |

- دکمهٔ «شروع/ادامهٔ یادگیری» همیشه به nextStation دیپ‌لینک می‌شود (اولین coreِ available؛ اگر هیچ‌کدام available نبود و core کامل شد → به «دروازهٔ فهم» /assessment).
- صفحهٔ معرفی فصل (/learn/[chapter]) حذف نمی‌شود (ارزش آموزشی can-do/صحنه) ولی گام اجباری نیست — از هدر پنل با پیوند ثانویه «معرفی فصل» در دسترس است. اسلایدهای آموزشی درون درس‌ها دست‌نخورده‌اند.

## ۷) Responsive (§۶.۲)

- **Mobile (~390px)**: تک‌ستونه؛ ردیف‌ها پشتهٔ عمودی؛ دکمه‌های قبلی/بعدی تمام‌عرض و لمس‌پذیر (≥۴۸px)؛ بدون اسکرول افقی.
- **Tablet (~768px)**: تک‌ستونه با max-width خوانا؛ همان چیدمان موبایل با فاصلهٔ بیشتر.
- **Desktop (~1440px)**: پنل با max-w-3xl در مرکز؛ هدر فصل و ردیف‌ها از عرض افقی برای خوانایی استفاده می‌کنند؛ دکمه‌های ناوبری بخش در پایین پنل به‌صورت دو نیمه.
- عدم Overflow چندجهته؛ reduce-motion برای انیمیشن‌های جزئی رعایت می‌شود.
