# مرور درس (Replay) و جریان پایان — TASK-HANASO-17

> الزام §۶ و §۷ مالک + DESIGN_DECISIONS L1–L6.

## ۱) دو حالت مستقل ایستگاه

| | Learning Mode | Review/Replay Mode (`?mode=review`) |
|---|---|---|
| ورود | CTAهای شروع/ادامه (Home/map) | ردیف‌های «مرور» map + «مرور دوبارهٔ این ایستگاه» |
| شروع walk | restore (اگر معتبر) یا block اول | **همیشه block اول** |
| محتوا | کامل (اسلایدها/صوت/تمرین) | همان — کامل (§6.1: «تمام اسلایدها و Audio») |
| ثبت نتیجهٔ تمرین | ✔ (exercise_answered) | ✔ (تمرین واقعی؛ بدون پاسخ FSRS مصنوعی) |
| POST `complete` | ✔ (idempotent `already:true` از قبل) | **هرگز** — پایان = پنل «مرور تمام شد» |
| Enrollment/پاداش | فقط اولین complete | هیچ |
| اثر بر Completion قبلی | — | صفر (ردیف سرور دست نمی‌خورد) |

## ۲) نقشهٔ یادگیری (رفع شکایت اصلی مالک)

- ردیف ایستگاه تکمیل‌شده: نشانگر انجام‌شده (CircleCheck) **باقی می‌ماند** + CTA ورود با آیکون تکرار (`Repeat2`) → `?mode=review` → درس از ابتدا.
- هیچ پیام «Completed مسدودت می‌کند» وجود ندارد — پیام «این ایستگاه را کامل کرده‌ای» فقط داخل بلوک تمرینِ از قبل انجام‌شده ظاهر می‌شود (رفتار Issue #102 موجود — نتیجه ثبت است، نه سد).
- پس از مرور: CTA بازگشت → map همان section (`?s=`).

## ۳) جریان پایان درس (Learning Mode)

```text
آخرین فعالیت الزامی تمام شد
→ POST complete (idempotent؛ شکست = اطلاع صادقانه + retry — TL-13 A-3 موجود)
→ پنل وضعیت «این ایستگاه را با موفقیت پشت سر گذشتی!» (غیرتعاملی — role=status)
→ یک CTA: «پایان درس و بازگشت به مسیر ←»  → /learn/{chapter}/journey?s={section-of-station}
→ زیر CTA (متن، نه دکمه): «درس بعدی: {title}» — فقط نمایش؛ باز شدن با انتخاب کاربر از map
→ لینک آرام «مرور دوبارهٔ این ایستگاه» (رفتار TL-10 حفظ شد؛ حالا = mode=review از ابتدا)
```

- بدون auto-open درس بعد (رفع §۷ مالک — CTA قبلی «رفتن به ایستگاه بعدی» حذف شد).
- مهر AIZEN فصل (`/complete` + «理解») برای گیت فصل حفظ شد؛ CTA «بازگشت به مسیر» آن هم به map همان فصل می‌رود.
- Refresh پس از پایان: پنل تکمیل می‌ماند (TL-10 §۶ موجود) — Regression تست شد.

## ۴) محاسبهٔ «همان Section»

`sectionOfStation(chapter, stationSlug)` — mapping داده‌ای از `units[]` (خالص، در journey.ts). صفحهٔ ایستگاه slugِ section را به runner می‌دهد؛ runner و صفحهٔ complete از آن برای `?s=` استفاده می‌کنند. فصل بدون units → section ضمنی (همان فصل) → `?s` حذف می‌شود.

## ۵) عدم تداخل با FSRS (§6.3)

- Replay ≠ Review: هیچ رویداد `fsrs_cards_enrolled` یا revlog از Replay ثبت نمی‌شود (enrollment فقط در اولین complete).
- نتایج تمرین در Replay از مسیر `exercise_answered` عادی می‌گذرند (تحلیل weak-point مجاز — سیگنال واقعی خطاست، نه مرور زمان‌بندی‌شده).
- Scheduler جداگانه ساخته نشد (آنتی‌پترن ۱ SR-UX).

## ۶) تست‌های پذیرش (§13-C/D مالک)

- C1: کلیک درس تکمیل‌شده → ورود از ابتدا (بدون پیام مسدود).
- C2: تمام بلوک‌ها + صوت در دسترس.
- C3: تمرین مجدد ممکن.
- C4: `already:true` — هیچ complete دوباره‌ای ثبت نمی‌شود (در Replay اصلاً POST نیست).
- C5: بدون پاداش تکراری.
- C6: Review History و Mastery دست‌نخورده.
- D1: تکمیل آخرین فعالیت → status غیرتعاملی.
- D2: مهر/پیام موفقیت.
- D3: فقط یک CTA.
- D4: بازگشت → همان map/section.
- D5: ردیف درس در map = انجام‌شده.
- D6: درس بعدی نمایش، بدون باز شدن خودکار.
- D7: refresh → وضعیت پایدار؛ Navigation دوباره Progress ثبت نمی‌کند (idempotent از قبل + تست).
