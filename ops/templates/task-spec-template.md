# قالب مشخصات تسک (task-spec) — HANASO

> تسک فقط با تکمیل **تمام فیلدها** از `Backlog` به `Ready` می‌رود؛ ناقص = Backlog می‌ماند.
> هر Issue در GitHub باید بر همین قالب بنا شود (عنوان: `TASK-<phase>-<nn> — <عنوان>`).

## فیلدهای الزامی (۱۲)

1. **شناسه/عنوان:** `TASK-<M#>-<nn>` + عنوان دقیق
2. **فاز/مایل‌استون** + **وضعیت** (Backlog/Ready)
3. **نقش Agent** (پیش‌فرض Builder) + **موازی‌بودن** با چه تسک‌هایی
4. **پیش‌نیازها** (تسک/گیت/دسترسی — با وضعیت صریح)
5. **هدف** (۱-۲ خط — چرا این تسک وجود دارد)
6. **محدوده:** چه ساخته می‌شود / چه ساخته **نمی‌شود**
7. **FEAT/AC مرتبط** (از رجیستری‌های KB)
8. **فایل‌ها/ماژول‌های در مالکیت** (مطابق `docs/architecture/MODULE-OWNERSHIP.md`)
9. **اسناد مطالعه** (مسیرهای دقیق KB، به ترتیب)
10. **Skillهای الزامی/اختیاری** (از ردیف متناظر `docs/engineering/skills/SKILL_SELECTION_MATRIX.md` — SKL-001..016 داخلی + EXT-001..012 خارجی)
11. **معیارهای پذیرش قابل‌آزمون** (تست‌پذیر، هر بند قابل تأیید/رد)
12. **تست‌های لازم** (نوع درست per testing-strategy) + **Definition of Done** (۵بند) + **نوع بازبین** (تازه-context / + مالک)
