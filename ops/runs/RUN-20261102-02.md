### ۳-۲) سوییچ اپ و مسیرها

- `modules/*/repository.ts`: اینترفیس‌ها **async** شدند (همان قرارداد، پیاده‌سازی Pg پشت همان interface)؛
  پیاده‌سازی‌های in-memory (DEV-ONLY بدون DATABASE_URL) دست‌نخورده از نظر رفتار.
- `lib/poc/stores.ts`: سوییچ DATABASE_URL → پیاده‌سازی‌های Pg؛ event store (ADR-۰۱۶ = M6) صادقانه in-memory ماند.
- `/api/ready`: با DATABASE_URL → چک واقعی DB (ok + serverVersion + latencyMs؛ fail → 503)؛ بدون آن → skipped (رفتار قبل).
- `/api/attempts` و `/api/progress`: فقط `await` اضافه شد؛ منطق/اعتبارسنجی بدون تغییر.

### ۳-۳) Worker و بکاپ (`apps/web/src/worker/`)

- `main.ts`: pg-boss 12 (`useListenNotify:false` — مستندسازی ناسازگاری LISTEN/NOTIFY با transaction-pooling)،
  صف‌ها `ops.backup` (۰۳:۳۰) و `ops.db-verify` (۰۴:۰۰) به وقت **Asia/Tehran**، shutdown سبک.
- `backup.ts`: `pg_dump -Fc` → تأیید `pg_restore --list` → نگهداشت KB (۷روز/۴هفته/۶ماه)؛ redact رمز از خطاها؛
  سازگاری نسخهٔ client/server چک می‌شود.
- `verify.ts`: گزارش شمارش جدول‌ها + عمق صف pgboss (همان کوئری برای دریل).

### ۳-۴) زیرساخت

- **Dockerfile:** کپی باندل‌های `.tools` + migrations + YAML محتوا؛ `pg_dump/pg_restore/psql/pg_isready` +

## ۴. تصمیم‌های ثبت‌شده

1. **migrator ران‌تایم drizzle به‌جای CLI drizzle-kit در image** — همان فرمت فایل و جدول bookkeeping؛
   بدون آوردن devDependency به image production.
2. **pg-boss polling-only پشت PgBouncer** — مستندات pg-boss: LISTEN/NOTIFY نیازمند session-pinned؛
   polling جایگزین رسمی. تصحیح یادداشت KB §۸-۴ (پارامتر `?pgbouncer=true` مال postgres.js است) در
   `docs/OPERATIONS_GUIDE.fa.md`.
3. **کپی باینری‌های pg از image postgres:18-alpine** به‌جای `apk add` — قطعیت هم‌major با سرور.
4. **single-role دیتابیس برای M0-10** (نقش `hanaso` مالک همه‌چیز در instance اختصاصی) — جداسازی نقش‌های
   app/migrator/backup به تسک سخت‌سازی M1 موکول شد (ثبت در PROJECT_STATUS).
5. **بکاپ فقط روی Volume محلی** — restic/S3 بدون دسترسی مالک ممکن نیست؛ به‌عنوان بدهی صریح ثبت شد.
