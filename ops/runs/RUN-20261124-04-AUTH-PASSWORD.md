## مبنا (بازنگری مالک — ۲۰۲۶-۱۱-۲۴)

> «این که گفتم ۴ روش ورود یعنی ۴ روش **بازیابی رمز عبور** بود؛ مگرنه قراره کاربر یه رمز خوب بذاره و هر بار با رمز و نام‌کاربریش وارد بشه. روش سادهٔ گوگل نیازی به رمز نداره — خوبیش سادگیشه. روش عبارت بازیابی می‌تونن نام کاربری بذارن. ایمیل/شماره باید تأیید بشه و بعدش بتونن وارد بشن. ظاهرش هم حرفه‌ای نیست، بررسی کن. از لحاظ امنیتی هم استاندارد و امن باشه.»

یعنی: M1 درست ساخته شد اما نقش‌ها جابه‌جا شدند — **نام کاربری + رمز عبور = روش اصلی ورود**؛ عبارت/ایمیل/گوگل/پیامک = **چهار درِ بازیابی رمز** (گوگل همچنان ورود یک‌کلیکی هم می‌ماند).

## معماری M2 (روی همان M1 — بدون سیستم موازی)

- **Migration 0007:** `users.username` (UNIQUE، NFKC-normalized `[a-z0-9_]{3,30}`) + ستون‌های زیرساخت پیامک (`phone`, `phone_verified_at`).
- **provider='password'** در همان `auth_identities` (providerAccountId = شناسهٔ خود کاربر؛ credential_hash = scrypt با نمک تازه در هر تغییر) — رمز در صفحهٔ روش‌ها «تغییر» می‌خورد نه «حذف» (`password_immutable`).
- **سیاست رمز** (ماژول خالص `password-policy.ts`، سمت کلاینت و سرور یکسان): ۸..۱۲۸ نویسه، blocklist رمزهای رایج، نباید نام کاربری/ایمیل را در خود داشته باشد، قبولی = طول ≥۱۲ یا ≥۳ از ۴ دستهٔ نویسه؛ متر قوت ۴ بخشی + چیپ دسته‌ها زنده.
- **نام کاربری:** نرمال‌سازی (NFKC، حروف کوچک، حذف @) + blocklist رزرو (admin/hanaso/…). حساب‌های گوگلی/عبارتی می‌توانند بعداً از تنظیمات نام کاربری بگذارند و با رمز وارد شوند — «کاربر عبارت می‌تواند نام کاربری بگذارد».
- **ثبت‌نام:** `POST /api/auth/register` — حساب فوراً فعال با session (ادغام مهمان مثل قبل)؛ ایمیل اختیاری فقط با transport فعال پذیرفته می‌شود (در غیر این صورت ۵۰۳ صادقانه) و با OTP «link» تأیید می‌شود.
- **ورود:** `POST /api/auth/login` — یک فیلد شناسه (نام کاربری **یا** ایمیلِ تأییدشدهٔ identity) + رمز. پاسخ یکسان برای شناسهٔ ناشناخته/رمز غلط (بدون افشا)؛ حساب بدون رمز (گوگلی/عبارتی) پیام صادقانهٔ «این در نیست» می‌گیرد (409 password_not_set).
- **بازیابی (درِ ۱) عبارت:** `POST /api/auth/recover/phrase` — عبارت + رمز جدید در یک گام تأییدشده → ست کردن رمز → **ابطال همهٔ sessionها** → session تازه. مسیر ورود روزمرهٔ عبارت حذف شد (route قبلی `/api/auth/mnemonic/login` بازنشسته).
- **بازیابی (درِ ۲) ایمیل:** `POST /api/auth/recover/email/request` (identifier → OTP با purpose جدید `password_reset` به ایمیلِ **تأییدشده**؛ anti-enumeration: پاسخ خنثی ۲۰۲ برای شناسهٔ ناشناخته/بدون ایمیل) + `verify` (کد + رمز جدید → ابطال همه → session).
- **بازیابی (درِ ۳) گوگل:** ورود با گوگل → «گذاشتن رمز» از تنظیمات امنیتی (بدون مسیر فیشینگ‌نما)؛ SET اولین رمز بدون نیاز به رمز فعلی (session گوگل خودش اثبات است) — تست شد.
- **بازیابی (درِ ۴) پیامک:** «به‌زودی» غیرفعال، فقط زیرساخت (ستون‌ها + نرمال‌سازی + bucketها از قبل).
- **تغییر رمز:** `POST /api/auth/password/change` — با رمز فعلی (اثبات تصاحب؛ session دزدی نمی‌تواند رمز را بچرخاند) → ابطال «سایر» sessionها، دستگاه فعلی می‌ماند.
- **UI بازطراحی‌شده (درخواست «حرفه‌ای»):** پوستهٔ مشترک `AuthShell` — نوار نیلی Aizen (motif青海波 + لبهٔ شنگرف + واترمارک藍染) کنار کارت فرم frame-ink با سایه-raised؛ دسکتاپ دو ستونه، موبایل تک‌ستونه؛ ورودی‌های LTR با focus شنگرف، CTA شنگرف با سایهٔ آفست سخت، دکمهٔ گوگل با لوگوی رسمی، متر قوت، نمایش/پنهان رمز، خطاها/موفقیت‌ها با `AuthBanner` یکدست. صفحات: login / signup (فرم → پیشنهاد عبارت → نمایش/آزمون) / recover (چهار در) + تنظیمات امنیتی بازنویسی‌شده (بخش رمز، بخش نام کاربری، کارت‌های روش، دستگاه‌ها).

## M3 — بازنگری دوم مالک: کتابخانهٔ اثبات‌شده + حذف اتوکامپلیت + تحلیل امنیتی متخصص

> «لیست کلماتت باید خیلی بلند بالا باشه، یه منبع داشته باشه… همون روش کیف‌پولی امن. تو فیلدهای بازیابی وقتی تایپ می‌کردی یه دنیا کلمه میاورد — باید خود یوزر تایپ کنه، اون لیست الکیه. از یه کتابخونه‌ای که قبلاً خودشو اثبات کرده استفاده کن. بعد به عنوان یه متخصص امنیتی کاملاً تحلیلش کن — میشه دور زدش یا نه؟»

- **موتور عبارت روی `@scure/bip39` 2.4.0** (اکوسیستم noble — حسابرسی‌شده، MIT؛ جانشین مدرن bip39): تولید ۱۲ کلمه با آنتروپی ۱۲۸ بیتی CSPRNG + اعتبارسنجی checksum از همان کتابخانه. خود لیست ۲۰۴۸ کلمه از خود کتابخانه می‌آید؛ فایل رسمی `bip-0039 english.txt` فقط مصنوع حسابرسی است و تست واحد **کتابخانه === فایل رسمی** را پین می‌کند (زنجیرهٔ تأمین). ماژول JSON دست‌ساز حذف شد.
- **حذف datalist از آزمون:** کاربر از حفظ تایپ می‌کند (یادآوری واقعی، نه بازی حدس حرف اول) و ۲۰۴۸ کلمه دیگر به باندل کلاینت نمی‌رسد.
- **سه اصلاح از بازبینی امنیتی:** (۱) سقف آزمون — ۵ پاسخ غلط روی یک ویزارد → ۴۲۹، ویزارد تازه آزاد؛ (۲) سپر زمانی scrypt در بازیابی ایمیلی — شناسهٔ ناشناخته/محدودشده همان زمانِ مسیر واقعی را می‌سوزانند (enumeration با latency هم ممکن نیست)؛ (۳) throttle قبل از صدور — صندوق ایمیلی محدود کد نمی‌سازد و کد قبلی را بازنشسته نمی‌کند.
- **باگ گرفته‌شده از راستی‌آزمایی پروداکشن:** مسیر «فعلاً نه» پیشنهاد عبارت، بنر موفقیت نادرست می‌داد → PR #189 با متن صادقانهٔ «هر وقت خواستی از تنظیمات امنیتی…».
