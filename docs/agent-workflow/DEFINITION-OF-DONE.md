# Definition of Done + گردش کار استاندارد Agentها — HANASO

> مطابق مأموریت §۵.۴ و §۶.۵ و KB ADR-015. نسخهٔ کامل چرخه: KB `task-lifecycle.md`.

## گردش کار استاندارد هر تسک

```
GitHub Issue → مطالعهٔ وابستگی‌ها (KB + ADR + Skill) → Branch/Worktree مستقل → پیاده‌سازی
→ تست (دروازه‌ها) → بازبینی مستقل (زمینهٔ تازه) → PR → Merge → Deploy (وقتی محیط فراهم است)
→ Verify → به‌روزرسانی مستندات/وضعیت
```

هیچ Agentی بدون ثبت Issue تغییری مهم انجام نمی‌دهد؛ هیچ Agentی مستقیماً روی main توسعه نمی‌دهد.

## Definition of Done (۵ بند — تسک فقط با تحقق همه «Done» است)

1. **تست‌ها سبز:** خروجی واقعی `pnpm lint/typecheck/test/build` (+e2e در صورت وجود) — بدون خروجی، ادعا بی‌اعتبار است.
2. **معیارهای پذیرش تأیید و فهرست‌شده:** هر AC تسک با تست/E2E پوشش یا به‌صورت مستند راستی‌آزمایی شده.
3. **مستندات به‌روز:** «کد تغییر کرد → کدام سند» (schema→DATA-ARCHITECTURE + فایل migration؛ مسیر جدید→SYSTEM-ARCHITECTURE؛ توکن/فونت→tokens + قرارداد طراحی؛ قاعدهٔ lint/CI→ADR-005) + `PROJECT_STATUS.md` در تغییرهای مهم.
4. **بازبینی انجام‌شده:** بازبین زمینهٔ تازه (هرگز سازنده) + یافته‌های S0..S2 حل و راستی‌آزمایی مجدد؛ تغییرهای امنیتی/داده = تأیید مالک.
5. **بدون بدهی پنهان:** TODO فقط با Issue ثبت‌شده؛ بدون feature-flag مرده/کد مرده.

## ثبت و گزارش (۴ نقطهٔ اجباری)

شروع (ردیف `AGENT_PROGRESS` + رکورد RUN) · milestone (به‌روزرسانی RUN) · مانع (`ops/BLOCKERS.md`) · پایان (گزارش تسک از قالب + وضعیت جدید در `TASK_REGISTRY` + ستون Project).

**قالب گزارش نهایی Agent (خلاصه):** چه کاری انجام شد · فایل‌های تغییرکرده · کامیت‌ها · تست‌های اجراشده و نتایج واقعی · باقیمانده‌ها · ریسک‌های کشف‌شده · وابستگی‌های باز · وضعیت Deploy — همه با شاهد قابل‌کلیک (commit/PR/خروجی فرمان).

> **محدودیت صادقانهٔ ثبت‌شده:** در این محیط اجرا، زیرAgent بازبین با زمینهٔ کاملاً جدا (بدون مشاهدهٔ مکالمهٔ سازنده، فقط با خواندن ریپو و KB) اجرا می‌شود — استقلال ورودی تضمین شده؛ استقلال زیرساختی مدل (همان ارائه‌دهنده) ثبت می‌شود.
