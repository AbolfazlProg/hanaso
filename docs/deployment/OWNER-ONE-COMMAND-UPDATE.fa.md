**تاریخ:** ۲۰۲۶-۱۱-۰۸ · **نسخهٔ هدف (Pin شده):** `1.0.0-tl08-cta01` @ کامیت `575b8dd8efeaa3e0cbc53bf134a6b71d80b130d4` (شاخهٔ `tl08-cta01`)
**CI روی همین کامیت:** سبز (ران `42466293496` — هر دو job تأیید + compose-smoke)

این راهنما **یک دستور واحد** برای نصب نسخهٔ جدید HANASO روی سرور (`https://learn.kotodama.ir`) است.
همهٔ مراحل داخل اسکریپت نسخه‌دارشدهٔ `infra/deploy/update-hanaso.sh` در همین ریپو مدیریت می‌شوند؛
دستور زیر فقط همان اسکریپت را از کامیت مشخص (`c8e42e4`) اجرا می‌کند.

## ۱) دستور واحد

این یک خط را در ترمینال **سرور** (به‌عنوان root) کپی و اجرا کنید — همین:

```bash
sudo bash -c 'export GIT_TERMINAL_PROMPT=0; R=""; for d in /srv/hanaso /opt/hanaso; do [ -d "$d/.git" ] && R="$d" && break; done; if [ -z "$R" ]; then git ls-remote https://github.com/AbolfazlProg/hanaso.git HEAD >/dev/null 2>&1 && git clone --quiet https://github.com/AbolfazlProg/hanaso.git /srv/hanaso && R=/srv/hanaso; fi; if [ -z "$R" ]; then echo "کلون ریپوی HANASO پیدا نشد — یک‌بار راه‌اندازی اولیه را در بخش ۲ همین راهنما انجام دهید"; exit 1; fi; git -C "$R" fetch origin tl08-deploy02 || { echo "git fetch ناموفق (احراز هویت یا شبکه) — بخش ۲ راهنما"; exit 1; }; W="$(mktemp -d /tmp/hanaso-upd.XXXXXX)"; git -C "$R" worktree add --detach "$W" c8e42e4d3b295a08473c76e8ff3d765dd2dd0fbf >/dev/null || exit 1; bash "$W/infra/deploy/update-hanaso.sh" "$@"; rc=$?; git -C "$R" worktree remove --force "$W" >/dev/null 2>&1 || true; exit $rc' hanaso-updater
```

این دستور **هیچ Secretی نمی‌پرسد، هیچ فایلی را دستی ویرایش نمی‌کند و هیچ فرمان اضافه‌ای لازم ندارد.**
هر تغییر آتی نسخه، فقط یک پیام با همین شکل (و SHA جدید) برایتان می‌آید.

## ۲) راه‌اندازی اولیه — فقط اگر دستور بالا گفت ریپو پیدا نشد

دو حالت وجود دارد:

**حالت الف — روی سرور git ندارید:** `apt-get install -y git`

**حالت ب — کلون وجود ندارد یا Credential ندارد** (یک‌بار برای همیشه؛ بعدش فقط دستور بخش ۱):

```bash
git config --global credential.helper store
printf 'protocol=https\nhost=github.com\nusername=AbolfazlProg\npassword=<PAT-شما-با-دسترسی-repo>\n' | git credential approve
# (توکن فقط در ~/.gitCredentials سرور ذخیره می‌شود — هرگز در ریپو/فرمان/لاگ نیست)
git clone https://github.com/AbolfazlProg/hanaso.git /srv/hanaso
```

سپس **همان دستور بخش ۱** را دوباره بزنید.

> اگر از قبل کلونی روی مسیر دیگری دارید، مسیرش را در ابتدای دستور به حلقهٔ `for d in …` اضافه کنید.

## ۶) چرا خودِ Agent منتشر نکرد؟

اتصال SSH از سندباکس به پورت ۲۲ سرور در هر سه تلاش کنترل‌شده **Timeout در فاز TCP** بود
(پورت ۲۲ از آن مسیر فیلتر است؛ سرور کاملاً سالم است — HTTPS و KOTODAMA هر دو پاسخ می‌دهند).
بنابراین انتشار نهایی طبق طراحی همین مأموریت، با **یک دستور توسط مالک** انجام می‌شود و
هیچ ادعای «منتشرشده» قبل از اجرای شما مطرح نیست.

## ۷) تضمین‌های KOTODAMA

اسکریپت فقط پروژهٔ compose با نام `hanaso` را هدف می‌گیرد و فقط سرویس‌های خودش را `up` می‌کند:
`compose down` هرگز اجرا نمی‌شود؛ کانتینر/دیتابیس/volume/ریورس‌پروکسی kotodama هرگز لمس نمی‌شود
(تنها چک HTTP ۲۰۰ به‌عنوان شاهدِ «صدمه نزدن»). این قید در ۱۳ سناریوی آزمون sandbox نیز
به‌صورت invariant سراسری بررسی شد (۷۲/۷۲ PASS).

## ۸) آزمون‌های انجام‌شده قبل از این تحویل

- **۱۳ سناریو در sandbox ایزوله** (ریپوی git واقعی + stub های docker/curl/df): مسیر سالم، به‌روزرسانی از
  نسخهٔ قبلی، نبودن Docker، کمبود دیسک، قطع GitHub، شکست Build، شکست Migration، شکست Health،
  اجرای دوبارهٔ بدون تغییر مخرب، رول‌بک، شکست بکاپ، خرابی شاهد kotodama، status فقط-خواندنی —
  همه PASS. جزئیات: `infra/deploy/sandbox-tests/README.md`.
- **محدودیت صادقانه:** Docker واقعی در سندباکس نیست؛ این آزمون‌ها جریان کنترل/ترتیب/رول‌بک/حفاظت را
  می‌سنجند نه خود build اپ. مسیر شبکه به پورت ۲۲ هم بسته است؛ استقرار واقعی با دستور شما انجام می‌شود.
