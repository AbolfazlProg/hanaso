# راهنمای انتشار HANASO V1.0.0-tl08-cta01 از کامپیوتر/دسترسی مالک

**تاریخ:** ۲۰۲۶-۱۱-۰۸ · **مأموریت:** TASK-HANASO-CTA-01 (جابه‌جایی CTA به انتهای معرفی کانا)
**کامیت انتشار:** `575b8dd8efeaa3e0cbc53bf134a6b71d80b130d4` (شاخهٔ `tl08-cta01`)
**نسخهٔ برنامه:** `1.0.0-tl08-cta01` · CI گیت‌هاب روی همین کامیت: **سبز**

## چرا خودِ Agent منتشر نکرد؟

اتصال SSH از سندباکس Agent به پورت ۲۲ سرور **در فاز TCP Timeout** شد (دو تلاش کنترل‌شده).
سرور کاملاً سالم است — HTTPS (پورت ۴۴۳) پاسخ می‌دهد و `learn.kotodama.ir` همین الان
نسخهٔ `1.0.0-tl08-a5r` را سالم سرو می‌کند. GitHub و CI هم سالم‌اند (ران سبز روی همین کامیت).
مشکل فقط مسیر شبکهٔ سندباکس→پورت ۲۲ است؛ چون شما مستقیماً با SSH وصل می‌شوید، انتشار نهایی
با یک فرمان از شما انجام می‌شود.

## پیش‌نیاز

- دسترسی SSH روت به `87.107.129.210` (که دارید).
- توکن گیت‌هاب (برای pull کد و در صورت تمایل push به GHCR).

## انتشار — سه فرمان

```bash
ssh root@87.107.129.210
```

روی سرور:

```bash
cd /srv/hanaso

# ۱) آوردن کامیت انتشار (اگر remote با توکن تنظیم نشده، فرمان بعدی را بزنید)
git fetch origin tl08-cta01 || \
  git fetch https://<توکن‌گیت‌هاب>@github.com/AbolfazlProg/hanaso.git tl08-cta01

# ۲) ساخت و انتشار با اسکریپت امن (build روی خود VPS — الگوی اثبات‌شدهٔ CP-11)
bash infra/deploy/deploy-local-build.sh \
  575b8dd8efeaa3e0cbc53bf134a6b71d80b130d4 \
  1.0.0-tl08-cta01 \
  <توکن‌گیت‌هاب>
```

اسکریپت به‌ترتیب خودکار انجام می‌دهد:

| قدم | کار                                                                          |
| --- | ---------------------------------------------------------------------------- |
| ۱   | fetch کامیت `575b8dd` (اگر محلی نبود)                                        |
| ۲   | ثبت image فعلی به‌عنوان هدف رول‌بک (از `.env`)                               |
| ۳   | `docker build` از همان کامیت در worktree موقت (بدون وابستگی شبکه)            |
| ۴   | push به GHCR با tagimmutable (اختیاری — با توکن)                             |
| ۵   | بکاپ `.env` → تعویض `HANASO_WEB_IMAGE`                                       |
| ۶   | `compose up -d web caddy`                                                    |
| ۷   | گیت سلامت: ۳۰×۲ ثانیه — باید `ok:true` **و** کامیت `575b8dd8` را برگرداند    |
| ۸   | `scripts/smoke.sh` (سلامت + RTL + ژاپنی)                                     |
| ۹   | چک شاهد KOTODAMA: `kotodama.ir` باید ۲۰۰ بماند (فقط چک — هیچ تغییری نمی‌کند) |

**اگر هر قدمی بعد از تعویض `.env` شکست بخورد، اسکریپت خودکار به image قبلی رول‌بک می‌کند.**

## راستی‌آزمایی بعد از انتشار

```bash
curl -sS https://learn.kotodama.ir/api/health
# انتظار: {"ok":true, "version":"1.0.0-tl08-cta01", "commit":"575b8dd8efeaa3e0..."}
```

سپس در مرورگر: `https://learn.kotodama.ir` → فصل ۰۱ → ایستگاه «ردیف あ» →
کارت «あ»: بعد از تماشای انیمیشن، خواندن باکس‌ها و **مثال‌های کاربردی**، در انتهای صفحه
باید ببینید:

- «معرفی این کاراکتر تمام شد! حالا نوبت توست.»
- دکمهٔ «شروع تمرین نوشتن ←»

با کلیک: صفحه به بالای بوم اسکرول می‌کند و تمرین با راهنما همان‌جا شروع می‌شود.

```bash
cd /srv/hanaso
sed -i 's|^HANASO_WEB_IMAGE=.*|HANASO_WEB_IMAGE=ghcr.io/abolfazlprog/hanaso:fdddad34edddc64ab6590bdd57fdb0e80c4bd1f1|' .env
```

(بکاپ‌های `.env` نیز با پسوند زمانی در همان پوشه موجودند.)

## تضمین‌های این انتشار

- **KOTODAMA دست‌نخورده:** اسکریپت فقط پروژهٔ compose مربوط به HANASO را `up` می‌کند
  (`web` و `caddy` از `infra/docker/docker-compose.yml`)؛ کانتینر/دیتابیس/volume دامنهٔ
  kotodama.ir اصلاً لمس نمی‌شود و فقط HTTP ۲۰۰ آن چک می‌شود.
- **دیتابیس HANASO بدون مهاجرت در این نسخه** — تغییر فقط UI/کامپوننت است؛
  `docker compose up -d web caddy` سرویس migrate را اجرا نمی‌کند.
- **بدون Secret در Git:** توکن فقط در فرمان شماست؛ در هیچ فایلی ذخیره نمی‌شود.
