# ADR-000 — Baseline Adoption of KB Architecture (ADR-001..017) + Re-validation 2026-11-01

**TL;DR (فارسی):** معماری مستندشدهٔ KB سالم، هم‌خوان و به‌روز است؛ همهٔ پین‌های فناوری با منبع رسمی npm در ۲۰۲۶-۱۱-۰۱ بازراستی‌آزمایی شدند و دقیقاً به‌روز بودند؛ بنابراین به‌عنوان خط‌پایهٔ این ریپو تبنی می‌شود — بدون موازی‌کاری دوباره.

- **مسئله:** مأموریت مالک (§۳) دستور داد انتخاب Stack بدون بررسی مجدد، قطعی فرض نشود. ۱۷ ADR و ۸۰ تصمیم در KB وجود دارد؛ باید مشخص شود چه چیزی تبنی و چه چیزی بازنگری شود.
- **گزینه‌ها:** (۱) تبنی KB به‌عنوان خط‌پایه + بازارزیابی نقطه‌ای · (۲) طراحی معماری از صفر · (۳) تبنی کور بدون راستی‌آزمایی.
- **شواهد:** بازارزیابی ۲۰۲۶-۱۱-۰۱ از npm registry و Docker Hub ([STACK-REVALIDATION](../research/STACK-REVALIDATION-2026-11-01.md)): next 16.4.3 · react 19.3.1 · typescript 7.0.2 (fallback 6.0.3 موجود) · tailwindcss 4.3.3 · drizzle-orm 0.45.4 · better-auth 1.7.14 · ts-fsrs 6.0.0 · pg-boss 12.38.0 · zod 4.6.7 · vitest 5.0.5 · playwright 1.64.1 · eslint 10.14.0 · pnpm 12.16.1 · wanakana 5.3.1 · postgres:18-alpine (به‌روزرسانی 2026-10-26) — همه مطابق پین‌های KB. سه ممیزی مستقل KB حکم READY داده بودند.
- **مقایسه:** گزینهٔ ۲ هزینهٔ کامل دوباره را می‌داد بدون شواهد نقص؛ گزینهٔ ۳ ادعای بدون-شاهد می‌ساخت (نقض اصل KB). گزینهٔ ۱ شواهد تازه تولید می‌کند و ریسک drift را صفر نگه می‌دارد.
- **تصمیم:** تبنی گزینهٔ ۱: KB ADR-001..017 خط‌پایهٔ الزام‌آور این ریپوست؛ هر انحراف = ADR جدید در این ریپو + ثبت spec-gap در KB. Spike TS7.0.2 در همین مأموریت **سبز** شد (OTD-004 → نتیجه ثبت شد).
- **مزایا:** حفظ زنجیرهٔ ردیابی کامل · صرفه‌جویی چند-هفته‌ای · یکپارچگی با حاکمیت Agent KB. **معایب:** وابستگی به به‌روزرسانی دوطرفه (KB↔ریپو).
- **هزینهٔ تغییر آینده:** جایگزینی هر فناوری خط‌پایه = ADR جایگزین + برنامهٔ مهاجرت (مثلاً خروج Drizzle→Prisma مستندشده در ADR-005 KB).
- **ریسک‌ها:** ریسک‌های ذاتی TRK-001..018 پذیرفته و پایش می‌شوند (TRK-003: انتشار امنیتی better-auth 2026-11-03 → به‌روزرسانی فوری).
- **وضعیت تأیید:** `PROPOSED` — تبدیل به CONFIRMED با گیت مالک OQ-014 (این ADR ورودی مستند آن است).
