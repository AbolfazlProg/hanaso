# ADR-006 — External Agent Skills: Two-Tier Skill Architecture & Enforcement

**TL;DR (فارسی):** معماری Skillهای HANASO دو-لایه شد: ۱۶ Skill داخلی (منبع canonical: KB، بدون نسخهٔ موازی) + ۱۲ Skill خارجی معتبر/رایگان/ممیزی‌شده (منبع canonical: `agent-skills/external/` همین ریپو، در commit بالادستی پین‌شده با PROVENANCE و مجوز). نصب هر دو لایه به `.claude/skills/` (خروجی تولیدی) با `scripts/sync-skills.sh`؛ استفاده از طریق Preflight اجباری + ماتریس انتخاب + جدول «Skills used» در PR الزامی شد. نصب Skill از شبکه ممنوع است؛ به‌روزرسانی فقط با ممیزی مجدد و PR.

- **مسئله:** مأموریت TASK-ENG (Issue #75، پیام مالک ۲۰۲۶-۱۱-۰۲): شکاف‌های تخصصی خارجی (E2E/Playwright، TDD، دیباگ سیستماتیک، عمق React/Next/PG، WCAG، UI-review، runtime-verification، STRIDE، SEO) با ۱۶ Skill داخلی پوشش داده نمی‌شوند؛ و compliance اعلام Skill در تسک‌ها اخیراً رها شده بود (RUN-20261101-04 و RUN-20261102-01 بدون بخش Skill).
- **گزینه‌ها:** (۱) کپی همهٔ Skillهای خارجی در KB و نصب از همان‌جا · (۲) vendoring در ریپوی محصول با نصب جداگانه · (۳) نصب زنده از رجیستری‌ها (`npx skills add`).
- **شواهد:** ممیزی ۲۱ مخزن + ۴ رجیستری (۲۰۲۶-۱۱-۰۲، آمار API تأییدشده — `SKILL_DISCOVERY_REPORT.fa.md`)؛ ممیزی امنیتی ۲۸ کاندید (اسکن + بازبینی خط-به-خط — `SKILL_SECURITY_AUDIT.md`)؛ ریسک واقعیِ دریافت محتوای راهنما از شبکه در web-design-guidelines که با vendoring محلی حذف شد؛ رجیستری‌ها (skills.sh و مشابه) برای نصب زنده طراحی شده‌اند ولی نسخه‌بندی/ممیزی را دور می‌زنند.
- **مقایسه:** گزینهٔ ۳ تکرارپذیری و ممیزی را نقض می‌کند (محتوای زنده = سطح تزریق و drift). گزینهٔ ۱ بار نگهداری KB را زیاد می‌کند و مرز «ویژگی‌های پروژه» و «دانش عمومی معتبر» را مخدوش می‌کند. گزینهٔ ۲ مرز را روشن نگه می‌دارد: هر لایه منبع canonical خودش را دارد، ریپوی محصول مالک نسخه‌ای است که Agentها واقعاً اجرا می‌کنند.
- **تصمیم:** مدل دو-لایه (۲): `agent-skills/external/` در این ریپو (فقط مجوزهای رایگان/متن‌باز Apache-2.0/MIT؛ commit پین‌شده؛ PROVENANCE.md الزامی؛ اسکریپت نصب PROVENANCE-less را رد می‌کند) + `scripts/install-external-skills.sh` و `scripts/sync-skills.sh` + ابزار دائمی ممیزی `scripts/audit-external-skills.py` + اسناد `docs/engineering/skills/` (رجیستری، ماتریس انتخاب، سیاست استفاده/نگهداری، ممیزی، ردشده‌ها) + الزام Preflight و جدول «Skills used» در `AGENTS.md` §۳ و PR Template.
- **مزایا:** تکرارپذیری کامل (SHA پین‌شده)؛ ممیزی‌پذیری (ابزار + PROVENANCE)؛ کشف یکسان برای همهٔ Agentها (۲۸ Skill در `.claude/skills/` + خواندن مستقیم برای runtimeهای بدون پشتیبانی بومی)؛ صرفه‌جویی Context (بارگذاری هدفمند ۲–۴ Skill). **معایب:** بار به‌روزرسانی دستی (ریسک کهنه‌شدگی — با بازبینی ماهانه کنترل می‌شود)؛ دو مسیر نصب به‌جای یکی.
- **هزینهٔ تغییر آینده:** افزودن Skill = PR با ارزیابی+ممیزی؛ حذف = PR با دلیل؛ جابه‌جایی KB↔ریپو در صورت نیاز آینده ممکن است ولی نیازمند ADR جدید.
- **ریسک‌ها:** (۱) drift بالادستی — هر PROVENANCE تاریخ راستی‌آزمایی دارد و سیاست نگهداری بازبینی ماهانه/رویدادمحور را اجباری می‌کند؛ (۲) تعارض راهنمایی Skill با ADR — با قواعد تقدم (تصمیم پروژه مقدم) حل و در PR ثبت می‌شود؛ (۳) Skillهای canary-مبدأ (EXT-009/012) — راستی‌آزمایی مجدد با هر ارتقای Next الزامی است.
- **وضعیت تأیید:** `VERIFIED` — نصب و کشف ۲۸ Skill در Worktree اجرا شد؛ ممیزی ۱۲/۱۲ PASS؛ آزمون‌های A-D مأموریت انجام شد (`SKILL_VERIFICATION_REPORT.md`)؛ دروازه‌های CI در PR متناظر.
