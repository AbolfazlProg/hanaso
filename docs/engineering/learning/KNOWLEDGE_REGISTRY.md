## ۱. قرارداد معماری (چرا این شکلی؟)

| قاعده                               | توضیح                                                                                                                                                                                                                                                                             |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **یک منبع حقیقت، بدون نسخهٔ موازی** | فصل‌های تألیف‌شده (`modules/curriculum/content/`) تنها منبعِ تألیف‌اند؛ رجیستری **ایندکسی مشتق‌شده و قطعی** از همان محتواست که در زمان بارگذاری ماژول ساخته می‌شود. هیچ داده‌ای دوبار تألیف نمی‌شود و drift امکان ندارد (تستِ دیجست قطعی‌بودن و حساسیت به محتوا را اثبات می‌کند). |
| **ثبتِ خودکار دانش جدید**           | به‌محض commit شدن محتوا، ثبتِ آموزش‌ها خودکار است — ساخته شدن رجیستری بخشی از همان ثبت اعتبارسنجی محتواست (EQA رجیستری را می‌سازد و گیت‌ها رویش اجرا می‌شوند). فرایند دستی و فراموش‌شدنی وجود ندارد؛ تستِ `AUTO-REGISTERS` اثباتش می‌کند.                                         |
| **ضد-تکرار**                        | هر داده یک خانهٔ تعریف یکتا دارد (`firstTaught` — فصل/ایستگاه/بلوک)؛ استفادهٔ بعدی «ارجاع» است نه «تدریس دوباره» (chapter-blueprint §سازگاری).                                                                                                                                    |
| **مواجهه ≠ تدریس**                  | مکالمهٔ محوری ابتدای فصل (قاعدهٔ سه‌منشأ) «مواجههٔ اولیه» است: در `exposureAt` ثبت می‌شود، هرگز در `firstTaught`. تا وقتی آموزش واقعی اجرا نشده، هیچ سؤالی نمی‌تواند آن را دانش قبلی فرض بگیرد — این دقیقاً همان چیزی است که EQA-8 تحمیل می‌کند.                                  |
| **نسخه‌بندی**                       | `KNOWLEDGE_REGISTRY_SCHEMA_VERSION` (شمارهٔ قرارداد) + `digest` (FNV-1a روی سری‌سازی مرتب مدخل‌ها) — هویت هر نسخهٔ محتوا. هر تغییر محتوا دیجست را جابه‌جا می‌کند.                                                                                                                 |

## ۲. ساختار مدخل (KnowledgeEntry)

```ts
{
  id: string,            // شناسهٔ یکتا — kanaId / wordId / expressionId / clusterId / 'mark-*' / 'glyph-*' / مفهوم
  kind: 'kana' | 'word' | 'grammar' | 'expression' | 'kana' | 'rule-mark' | 'derived-glyph' | 'concept',
  surface: string,       // شکل استاندارد (گلیف / ترم / الگو / عبارت)
  reading?, romaji?, meaningFa?,
  firstTaught: { chapterSlug, stationSlug, stationOrder, blockId?, globalIndex },  // خانهٔ تعریف
  exposureAt?: KnowledgePoint[],   // مواجهه‌های مکالمهٔ لنگر — جدا از تدریس
  prerequisites: string[],         // روابط پیش‌نیازی (گلیف‌های پایه + قواعد نشانه / …)
}
```

منابع ثبت در ترتیب دِک (به‌محض commit محتوا):

| بلوک محتوا                                                      | چه چیزی ثبت می‌شود                                                          |
| --------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `kana-card`                                                     | کانای رجیستری (پیش‌نیاز = گلیف پایه + قاعدهٔ نشانه)                         |
| `vocab-card`                                                    | واژه (term/reading/meaning + exposureAt خط مکالمه)                          |
| `expression-card`                                               | عبارت کاربردی                                                               |
| دِک‌های قاعده (`rule-card/rule-step/rule-prereq/rule-contrast`) | قواعد نشانه در ایستگاه قاعدهٔ خود + هر فرم مشتقِ نمایش‌داده‌شده (`glyph-*`) |
| خوشه‌های گرامر                                                  | لنگر ایستگاهِ نگه‌دارندهٔ تمام lineRefهای خوشه (قاعدهٔ eqa/model)           |
| هر ایستگاه                                                      | `objectiveCode` + `teachesConcepts` به‌عنوان مفهوم                          |

وارثتی زنجیرهٔ فصل‌ها: دانشِ ورودیِ هر فصل = مجموعهٔ کاملِ آموزشِ زنجیرهٔ `prerequisiteChapterSlug` (بازگشتی). `cumulativeBeforeStation` (دانشِ دقیقاً پیش از هر ایستگاه — قاعدهٔ ترتیبِ دِک EQA-8) و `cumulativeByStation` (شامل خود ایستگاه) هر دو موجودند.

## ۳. جست‌وجوی سریع و دقیق

```ts
searchKnowledge(registry, {
  query: 'だいがく', // متن آزاد: surface / reading / romaji / id
  kinds: ['word'], // فیلتر نوع
  chapter: 'first-meeting-01', // فصل اولین تدریس
  taughtBy: { chapterSlug, stationSlug }, // فقط دانشِ تدریس‌شده تا آن نقطه
  exact: false,
  foldScript: true,
  limit: 20,
});
```

- نرمال‌سازی query (trim/lower) + **تاخیِ خط** (katakana↔hiragana) با `foldScript` برای جست‌وجوی خط-ناوابسته.
- ایندکس‌های O(1): `byId` / `bySurface` / `bySurfaceFolded` / `byReading` + اسکن خطی برای substring (جست‌وجوی سریع و دقیق).
- `wordsInSurface(registry, text)` — واژه‌های ثبت‌شدهٔ موجود در متن پیرامونی (کاوشگر R3؛ اولویت طولانی‌ترین واژه).
- `taughtAtPoint` / `isTaughtAtOrBefore` / `taughtSetAt` — پاسخ‌های مستقیم پرسش‌های زمان‌بندی.

**CLI نسخهٔ انسانی:** `cd apps/web && npx tsx scripts/knowledge-registry-snapshot.mjs` — اسنپشات JSON کامل + دیجست در `ops/reports/knowledge-registry.snapshot.json` + مثال‌های جست‌وجو روی stdout.

## ۴. گیت‌های دائمی CI (که این رجیستری را تضمین می‌کنند)

| گیت                                 | چه چیزی را غیرممکن می‌کند                                                                      |
| ----------------------------------- | ---------------------------------------------------------------------------------------------- |
| **EQA-8 · R1/R2**                   | استفاده از کانا/قاعدهٔ تدریس‌نشده در هر سطح محتوا (شامل گزینه‌های انحرافی، بازخوردها، تابلوها) |
| **EQA-8 · R3**                      | پیش‌فرض‌گرفتن واژهٔ ثبت‌شده در متنِ پیرامونیِ پیش از تدریسش                                    |
| **EQA-8 · R4**                      | کانجی ثبت‌نشده در سطح سنجش = خطای قابل‌پیگیری (نه پذیرش بی‌صدا)                                |
| **EQA-8 · R5**                      | سنجش مفهوم پیش از بلوک تدریس‌کننده — حتی درون همان ایستگاه (ترتیب بلوک)                        |
| **EQA-10 · C-first-engage**         | آموزشِ مقدار کم بدون درگیرسازی سادهٔ بلافاصله (difficulty 1)                                   |
| **EQA-10 · C-worked-before-decode** | تمرین کاربردی بدون مثال الگو‌شدهٔ قبلی                                                         |
| **EQA-10 · C-guided-first**         | تمرین مستقل (d3) بدون سنجش هدایت‌شدهٔ (≤d2) قبلی همان مفهوم                                    |
| **EQA-10 · C-type-structure**       | ایستگاه بدون بلوک الزامی نوع خودش                                                              |
| **رجیستری (سوئیت مستقل)**           | دیجست غیرقطعی، id تکراری، ثبتِ غیرخودکار، زنجیرهٔ پیش‌نیاز شکسته — همه در تست رد می‌شوند       |

معافیت‌ها: نقض‌های شناخته‌شدهٔ محتوای موجود (بدهی مرحله‌ای) صریح و Issue-دار در `content/eqa-waivers.ts` ثبت شده‌اند؛ هر یافتهٔ جدید بدون معافیت CI را می‌شکند. سه درسِ پایلوت بازسازی‌شده (`stn-kana-hd1`, `stn-kana-hy1`, `stn-kana-kx1`) بدون هیچ یافته‌ای سبزند — استاندارد جدید در خود محتوا زندگی می‌کند.

## ۵. مرزهای صادقانه

- **لایهٔ درفتِ Lesson-Engine:** قواعد `L-STAGING` و `L-PREREQ-SURF` روی درفت‌ها (سطح تألیف آینده) اجرا می‌شوند؛ زمان‌بندی کامل تدریس→سنجش روی شکل runtime کامپایل‌شده در EQA-8 نهایی می‌شود.
- **مکالمهٔ لنگر:** مواجههٔ اولیه طبق مأموریت §۳ معاف از بررسی‌های پیش‌نیازی است (سه‌منشأ)؛ زمان‌بندی درکِ خط نزد EQA-1 لایهٔ ۲ می‌ماند.
- **سطوح خود-پشتیبان:** مثال‌های «لحظهٔ خواندن» (معنی/خوانش همراه متن) و تابلوهای دوزبانه (گلاوس) — معنی همان‌جا هست، پس دانشِ پیش‌فرض گرفته نمی‌شود؛ کانجیِ آن‌ها هشدار (EQA-9) است نه خطا.
- **معناشمولی عمیق:** آنچه ماشین قطعی نمی‌تواند (ظرفیت معنایی صورت سؤال) به پروتکل انسانی EQA-9 می‌ماند — همان طبقه‌بندی TASK-LEARNING-04.
