## ۲. قواعد غیرقابل نقض

1. **Snapshot ممنوع:** اکتفا کردن به Summary/گزارش Agent قبلی به‌جای منابع اصلی، نقض این پروتکل است.
2. **تعارض اسناد:** اگر دو سند تعارض دارند، پیش از Implementation آن را گزارش کن (Issue/کامنت) — انتخاب خودسرانه ممنوع. مرجع حل تعارض‌های توالی آموزشی: `LEARNING_SEQUENCE_POLICY.md` (بستن C1).
3. **گیت‌های EQA:** هر تغییر محتوای آموزشی از `pnpm eqa` عبور می‌کند. نقض جدید = یا اصلاح محتوا یا معافیت ثبت‌شده با Issue — «سبز کردن تست با تغییر خودسرانهٔ قاعده» ممنوع.
4. **تصمیم‌های مالک (D-1..D-5 → DD-117..121):** این‌ها **بسته** شده‌اند و دوباره به‌عنوان سؤال باز از مالک پرسیده نمی‌شوند؛ بازنگری فقط با فرایند تغییر تصمیم KB (شاهد جدید + تأیید مالک).
5. **بدون تغییر ناخواسته Product Runtime:** هر PR فقط scope اعلام‌شدهٔ Task را لمس می‌کند؛ diff خارج از scope = بازبینی مجدد.
6. **بدون دستور مخرب Git** (Force Push / Reset / Clean / پاک‌کردن تاریخچه) و **بدون دست‌کاری Production DB** بدون مجوز صریح Task.

## ۳. معیار اتمام از Checkout تمیز

```bash
git clone <repo> /tmp/verify && cd /tmp/verify && git checkout <merge-commit>
pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test && pnpm eqa && pnpm build
```

- همهٔ دروازه‌ها از درخت تمیز سبز شوند (نه فقط از working directory عامل).
- گزارش نهایی باید شامل خروجی واقعی همین اجرا باشد.

## ۴. گزارش نهایی — بخش‌های الزامی

هر گزارش پایان Task باید این دو بخش را داشته باشد (الزام TASK-LEARNING-04):

### `Skills Used`

فهرست Skillهای واقعاً خوانده/اجرا‌شده با کاربرد هر یک — نه فهرست تشریفاتی.

### `Source Documents Reviewed`

فهرست اسناد/Issueهای واقعاً خوانده‌شده با مسیر — «خواندن» یعنی مطالعهٔ متن، نه عنوان.

(+ ساختار گزارش کامل: `ops/templates/task-report-template.md` در KB — SKL-012.)
