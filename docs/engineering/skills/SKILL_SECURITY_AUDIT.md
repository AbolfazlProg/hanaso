# Skill Security Audit — TASK-ENG external skills

> **TL;DR (فا):** ممیزی امنیتی همهٔ Skillهای خارجی پیش از نصب: اسکن خودکار با ابزار داخل ریپو + بازبینی دستی خط-به-خط همهٔ SKILL.mdها و اسکریپت‌ها. نتیجه: هر ۱۲ Skill منتخب PASS؛ یک ریسک واقعی (دریافت قواعد از شبکه در web-design-guidelines) با تطبیق محلی حذف شد؛ موارد پولی/شبکه‌ای مجاز شمرده نشدند.

**Audit date:** 2026-11-02 · **Auditor:** engineering agent (TASK-ENG, Issue #75) · **Scope:** 28 candidate skills examined (12 vendored + 16 evaluated-and-rejected) from 21 assessed repositories.

---

## 1. Methodology

Two layers, both required before a skill is vendored:

1. **Automated first-pass** — `scripts/audit-external-skills.py <dir>` (committed to this repo as permanent tooling) scans every file for:
   - `curl|bash` / `wget|sh` pipe-to-shell, destructive filesystem ops (`rm -rf /`, `mkfs`, `dd`), privilege escalation (`sudo`, `chmod 777`);
   - secret access (`~/.ssh`, `id_rsa`, `.env` reads, token patterns `ghp_`/`github_pat_`/`AKIA…`);
   - exfiltration surfaces (Discord/Slack/Telegram webhooks, pastebin);
   - prompt-injection phrasing ("ignore previous instructions", "disregard…", "override all rules/policies", "developer mode", "jailbreak");
   - VPS/global service mutations (`systemctl restart`, `crontab`), force-push, unpinned global installs;
   - full external-URL inventory (network surface) and frontmatter validity (name == folder, description present).
2. **Manual line-by-line review** — a human-level read of every vendored `SKILL.md` and every bundled script (`with_server.py`, `find-polluter.sh`, all example scripts), plus the runtime behavior each skill prescribes.

**Rule:** automated findings are triaged by a reviewer (false positives possible — e.g. prose merely containing the word "telemetry"); HIGH/MEDIUM items block vendoring unless mitigated by a documented adaptation.

## 4. Prohibited behaviors — verification that no vendored skill requires them

Checked against every vendored file: none instructs reading `.env`/`.ssh`/credentials; none pipes network content to a shell; none requires sudo or global VPS mutations; none posts project data anywhere (the only network-touching behavior was web-design-guidelines' rule fetch — removed by adaptation); none attempts to override project instructions (the two "process-discipline" skills — TDD, debugging — push workflow rigor, and their hard rules are constrained by the precedence rules in the usage policy §4 and each PROVENANCE's limitations field).

## 5. Ongoing assurance

- The audit tool is committed (`scripts/audit-external-skills.py`) and re-run on every update (maintenance policy §2) — new upstream content cannot enter without a fresh automated + manual pass.
- PROVENANCE.md is mandatory per skill; the install script **refuses** to install a skill folder without it.
- Registry consistency check (maintenance policy §6) catches drift between disk and registry.
