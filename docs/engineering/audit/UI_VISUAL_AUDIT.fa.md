## ۲. نتایج فنی خودکار (۱۶/۱۶ سبز)

| بررسی                                    | نتیجه                                            |
| ---------------------------------------- | ------------------------------------------------ |
| کد وضعیت HTTP                            | ۸/۸ مسیر × ۲ viewport = **200**                  |
| سرریز افقی (`scrollWidth > clientWidth`) | **0px در همه** (بدون عنصر سرکش)                  |
| خطای کنسول                               | **صفر** (به‌جز مورد محلی زیر)                    |
| تصاویر بدون alt                          | 0 (کل صفحات 0 تصویر — چون دارایی هنری هنوز نیست) |
| خطای صفحه (pageerror)                    | صفر                                              |

**دو مورد بررسی‌شده و رفع‌توضیح:**

1. **`/learn` دو 500 محلی در سندباکس** — علت: نبود `DATABASE_URL` در محیط آزمون (پوشهٔ fallback در حافظه). در **Production همان فراخوانی 200** است: `{"stage":"A_selfcheck","status":"active"}` برای `poc-user`. نتیجه: باگ نیست؛ رفتار fail-closed صحیح است.
2. **`/poc/lesson` چند `ERR_ABORTED` روی `?_rsc=`** — لغو prefetch ناوبری React معیار است؛ خطا نیست.

## ۳. یافتهٔ مهم Production: صدای جایگزین 404

- `https://learn.kotodama.ir/poc-audio/manifest.json` → **404** · `.../s-cafe-morning-01-l1.wav` → **404**
- علت ریشه‌ای: `infra/docker/Dockerfile` مرحلهٔ `pnpm gen:audio` را **اجرا نمی‌کند** و `public/poc-audio/` در git هم ignore شده است.
- اثر: پلیر دیالوگ در Production **بی‌صدا** اجرا می‌شود (طراحی graceful است و خطا نمی‌دهد، اما تجربهٔ مرور مالک نصفه است).
- اصلاح پیشنهادی (تسک کوچک، به Master Roadmap منتقل شد): افزودن `RUN pnpm --filter web gen:audio` به مرحلهٔ build + یک ادعای smoke.

## ۴. ممیزی کیفی ابعاد طراحی (جمع‌بندی VLM + بازبینی کد)

### ۴-۱) هویت بصری

پالت/توکن‌های Aizen (کاغذ گرم، جوهر، شنگرف، نیلی، قاب newspaper، موتیف 青海波) **درون کد کامل و منسجم‌اند** — بهترین اجرایش در `/poc/ui` (۷.۵/۱۰). در صفحات محصول، اجرای امضاها ناهمگن است: خانه ترکیب باند نیلی+کاغذ را «شکسته» نشان می‌دهد و practice تقریباً بی‌رنگ است. **جمع‌بندی: مشکل، سیستم طراحی نیست؛ اعمال یکنواخت آن در صفحات است.**

### ۴-۲) چیدمان و فاصله‌گذاری

سلسله‌مراتب کلی درست (عنوان←توضیح←کارت). دو ایراد تکرارشونده: whitespace زیاد در `/poc/lesson` (حس خالی) و فوتر شلوغ/متنی در `/learn` و `/poc/dialogue` (موبایل: «بیش از حد شلوغ و پر از متن‌های تکنیکال»).

### ۴-۳) تایپوگرافی

فونت فارسی سلف‌هاست (۱.۷۳MB بودجه‌بندی‌شده) و ژاپنی با جزیرهٔ `lang="ja" dir="ltr"` + روبی FuriganaText — **زیرساخت درست و تست‌شده**. ایراد VLM: هم‌ترازی وزن/اندازهٔ فونت لاتین/ژاپنی با فارسی هنوز نهایی نشده.

### ۴-۴) کیفیت کامپوننت‌ها

۹ کامپوننت RTL پایه موجود و تست واحد دارند. ایرادهای ممیز: نبود حالت‌های بصری واضح selected/hover-عمیق (خصوصاً assessment و practice)، دکمه‌ها «کمی ساده/legacy»، نبود scrollbar هماهنگ با تم.

### ۴-۵) تعامل

ساختار حالت‌ها (hover/focus/disabled/loading) در `button.tsx` تعریف شده و CTA اصلی هم offset-shadow امضای Aizen دارد — اما در صفحات practice/assessment بازخورد لحظه‌ای انتخاب کم است.

### ۴-۶) Responsive و دسترس‌پذیری

دو viewport سبز؛ `aria-current` روی استپر، `role="alert"` روی خطا، `aria-label="مراحل واحد"` — نشانه‌های خوب. نبود دارایی تصویری (0 img) کنتراست/alt را غیرقابل‌ممیز گذاشته — با آمدن شخصیت‌ها باید alt عربی/فارسی الزامی شود. `prefers-reduced-motion` در globals رعایت شده (prefers-reduced-motion: reduce → انیمیشن‌های transform خاموش).

## ۵. پاسخ به ۸ پرسش §۳.۵

1. **کدام صفحات فقط Prototype؟** `/poc/practice`، `/poc/t2-eval`، `/poc/dialogue` (از نظر تجربه؛ پخش‌کننده‌اش فنی‌اً قوی است).
2. **کدام UI Foundation دارند؟** `/`، `/learn`، `/poc/lesson`، `/poc/assessment`، `/poc/ui`.
3. **کدام قابلیت واقعی دارند؟** `/learn` (دادهٔ واقعی DB + استپر زنده)، `/poc/dialogue` (پخش چندگوینده با زمان‌بندی دقیق)، `/poc/assessment` (نمره‌گذاری سروری + ثبت در DB).
4. **کدام صفحات بصری‌ضعیف‌اند؟** `/poc/practice` (۴/۱۰)، `/poc/t2-eval` (۳/۱۰)، فوتر `/poc/dialogue`، خانه (ترکیب ناهمگن).
5. **چه چیزهایی قبل از عرضه باید حل شود؟** (الف) تولید صدا در build [D-01]؛ (ب) پنهان‌سازی متن فنی [D-04]؛ (ج) حالت‌های انتخاب در assessment/practice؛ (د) پالایش فوترها.
6. **کدام کامپوننت‌ها اصلاح شوند؟** OptionCard (حالت‌های انتخاب)، Footer (ساختار)، SpeedControl (تراکم موبایل)، متغیرهای spacing صفحهٔ درس.
7. **آیا توکن‌های Aizen درست استفاده شده‌اند؟** **بله در سطح توکن** (tokens.css مرجع واحد، tokens-gate تست سبز، بدون hex خام در کامپوننت‌ها)؛ **ناقص در سطح اعمال یکنواخت** (صفحات practice/dialogue-footer از امضاها کمتر بهره می‌برند).
8. **آیا Design System به محصول باکیفیت منجر شده؟** **سیستم = بله (پایهٔ محکم)؛ محصول = هنوز نه** — کیفیت تجربه فعلاً ۴-۶.۵/۱۰ است چون محتوا/دارایی/حالت‌ها ناتمام‌اند، نه چون جهت هنری اشتباه است.
