WHAT'S NEW IN v9 (HANASO-16)
  1. The release bundles EVERYTHING pending from tl14-r01 (the slide-by-slide
     rule-teaching redesign — it rolled back and never shipped) PLUS the new
     progressive learning journey: /learn now auto-selects the ACTIVE chapter

     tl14-r01 mis-rollback: it now distinguishes (a) application failures
     [rollback], (b) deploy-caused public-path breakage [rollback], (c) a
     PRE-EXISTING broken front line [stop BEFORE any change, nothing rolled
     back, clear repair instructions] and (d) hairpin/self-probe artifacts
     [release stands, status EXTERNAL_UNVERIFIED]. Statuses are recorded in
     the update history file (PUBLIC_CLASSIFICATION).

IMPORTANT — READ BEFORE THE FIRST RUN
  As of 2026-11-11 the PUBLIC endpoint of BOTH learn.kotodama.ir AND
  kotodama.ir is verifiably broken WORLDWIDE (verified from 5 countries: TLS
  completes with a valid certificate, then the connection is closed with an
  empty reply; port 80 refused). This is a PRE-EXISTING front-line (host
  HAProxy/nginx) outage — NOT the HANASO application. The v3 updater will
  detect this in its PREFLIGHT and STOP BEFORE CHANGING ANYTHING, printing
  INGRESS_PREEXISTING_BROKEN with repair hints (systemctl status haproxy
  nginx; ss -tlnp | grep -E ':80|:443'; docker ps). FIX THE FRONT LINE
  FIRST, then run the same one-liner — it will then deploy and verify
  normally. To deploy anyway despite the unverified public path, prefix the
  env:  HANASO_ALLOW_UNVERIFIED_INGRESS=1  (the app itself is still fully
  gated locally: health, version, migration, smoke).
