WHAT THE LINE DOES, STEP BY STEP
  1. pins R (tooling commit), W (the bootstrap file's SHA-256), D (the
     product release commit) and T (a temp path);
  2. downloads infra/deploy/bootstrap-hanaso.sh AT COMMIT R — first via
     api.github.com, and if that path fails via a codeload tarball with a
     single-file extract;
  3. verifies the downloaded file is BYTE-IDENTICAL to the pin (sha256sum
     -c) — a mismatch aborts with NOTHING executed;
  4. runs it with HANASO_TARGET_VERSION/HANASO_DEPLOY_SHA(tooling)/
     HANASO_TARGET_SHA(product) set — the bootstrap re-verifies R and D
     exist in the repository, then executes the updater strictly from
     commit R, which builds the image from commit D on the server, runs the
     staged swap, the health gate, the smoke gate, and records the update
     history for rollback.

OPTIONAL SUBCOMMANDS — append the word INSIDE the quotes, right before the
final closing quote:

  … bash "$T" rollback'   # app-level rollback to the previous image
                          # (database and volumes are NEVER touched)
