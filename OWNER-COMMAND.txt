DELIVERY PATHS (same evidence-based order as v11: api.github.com first,
codeload.github.com as the fallback; raw was dropped in v10 — its IPs are
unreliable from this VPS):
  1/2  api.github.com       contents API at the pinned tooling commit
  2/2  codeload.github.com  tarball of the pinned tooling commit,
                            single-file extract
  The bootstrap's REAL SHA-256 is checked BEFORE anything is executed — a
  corrupted, truncated or tampered download can never run. curl errors are
  printed verbatim; nothing is hidden. If BOTH downloads fail the command
  aborts having changed NOTHING.

THE COMMAND — ONE line, copy it WHOLE (this exact line is also the one the
sandbox drill infra/deploy/sandbox-tests/run-h21.sh executes):

bash -c 'R=5870eaf3892c7cb8a1bcfa3ec058d77474e3ad10; W=d4736bd8d676ac10f8c2832c3888e8f2a95eff72d2088a65088a9c5d85fb2073; D=33304b1f2b402d70c3090f447d44e2139adcc6b7; T=/tmp/hanaso-bootstrap-h21.sh; (curl -fsSL --connect-timeout 10 --max-time 60 -H "Accept: application/vnd.github.raw" "https://api.github.com/repos/AbolfazlProg/hanaso/contents/infra/deploy/bootstrap-hanaso.sh?ref=$R" -o "$T" || curl -fsSL --connect-timeout 10 --max-time 300 "https://codeload.github.com/AbolfazlProg/hanaso/tar.gz/$R" | tar -xzO "hanaso-$R/infra/deploy/bootstrap-hanaso.sh" > "$T") && echo "$W  $T" | sha256sum -c - && HANASO_TARGET_VERSION="1.0.0-hanaso21-r01" HANASO_DEPLOY_SHA="$R" HANASO_TARGET_SHA="$D" bash "$T"'

  (If you are NOT root, start the line with: sudo bash -c ' … ' — the whole
  single-quoted payload stays exactly the same.)

WHAT THE LINE DOES, STEP BY STEP
  1. pins R (tooling commit), W (the bootstrap file's SHA-256), D (the
     product release commit) and T (a temp path) — all inside the quoted
     bash -c payload, nothing undefined can leak in from your shell;
  2. downloads infra/deploy/bootstrap-hanaso.sh AT COMMIT R — first via
     api.github.com, and if that path fails (rate-limit, network, TLS) via a
     codeload tarball with a single-file extract;
  3. verifies the downloaded file is BYTE-IDENTICAL to the pin (sha256sum
     -c) — a mismatch aborts with NOTHING executed;
  4. runs it with HANASO_TARGET_VERSION/HANASO_DEPLOY_SHA/HANASO_TARGET_SHA
     set — the bootstrap re-verifies R and D exist in the repository, then
     executes the updater strictly from commit R, which builds the image
     from commit D on the server, runs the staged swap (postgres →
     pgbouncer → migrate → web+worker), the health gate, the smoke gate,
     and records the update history for rollback.

OPTIONAL SUBCOMMANDS — append the word INSIDE the quotes, right before the
final closing quote:
  … bash "$T" status'     # read-only health report (all three tiers)
  … bash "$T" rollback'   # app-level rollback to the previous image
                          # (database and volumes are NEVER touched)
